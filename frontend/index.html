Engine 1

Dense Semantic Search

Uses SentenceTransformers with all-MiniLM-L6-v2 to convert document chunks and queries into 384-dimensional dense vectors. These capture semantic intent and concept matching (e.g. matching "materials" to "steel" or "cement"). Meta's FAISS library indexes these vectors to enable fast nearest-neighbor (L2 distance) querying.

Engine 2

Sparse Lexical Search

A custom BM25 sparse retriever computes term frequencies (TF) and inverse document frequencies (IDF) dynamically. This ensures that unique keywords, proper nouns, and specific names (like "ACC", "Infinia", "445+", "zero-cost") are matched exactly, compensating for any semantic generalities in the dense model.

Merging Strategy

Reciprocal Rank Fusion (RRF) Re-ranking

To combine the ranking results of Dense and Sparse engines without needing to normalize scores with incompatible scales, we implement Reciprocal Rank Fusion (RRF). The merged score of a document chunk $d$ is defined as:

$$RRF\_Score(d) = \sum_{m \in \{dense, sparse\}} \frac{1}{60 + Rank_m(d)}$$

We retrieve the top-10 chunks from dense search and all candidate matches from sparse search, re-rank them using RRF, and select the top-5 highest-scoring chunks to feed to the LLM. This provides a balance of semantic contextualization and strict keyword accuracy.

Safety Guardrail

Zero-Hallucination Grounding Prompt

The top-5 re-ranked context chunks are formatted as references and sent to the Groq API running llama-3.3-70b-versatile. The LLM is restricted via a strict system prompt to answer ONLY from the provided context. If the query cannot be answered by the context, it must strictly refuse to answer rather than fabricating details. Indicative prices are highlighted as variable in final answers.
